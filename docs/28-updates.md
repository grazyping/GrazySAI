# Обновление программы

Как GrazySAI узнаёт о новой версии и ставит её (`crates/paint-app/src/update.rs`). Своего сервера
нет: всё идёт через выпуски на GitHub.

## Проверка

- При запуске, в фоне — один запрос `GET https://api.github.com/repos/grazyping/GrazySAI/releases/latest`
  (без ключа; лимит GitHub — 60 запросов в час с одного адреса). Ничего о пользователе не
  отправляется, кроме самого запроса.
- Выключается в «Помощь → Проверять обновления при запуске» (настройка `check_updates`).
  Вручную — «Помощь → Проверить обновления…».
- Нашлась версия новее — справа в строке меню появляется надпись «⬆ Вышла версия X»; по щелчку
  окно «Обновление» с заметками выпуска на языке интерфейса (раздел `## English` или
  `## Русский` из заметок). Больше программа ничего не показывает и не мешает.
- Без настроек (`PAINT_SETTINGS=off`, прогоны виртуальным пером) при запуске не проверяет.

## Установка

1. Скачивается архив этой системы (`GrazySAI-X-windows-x86_64.zip` или `…-linux-x86_64.tar.gz`)
   системным `curl` в папку `.grazysai-update` рядом с программой.
2. SHA-256 архива сверяется с полем `digest` из ответа GitHub (своя реализация SHA-256, без
   зависимостей).
3. Распаковка системным `tar` (в Windows — `System32\tar.exe`, он умеет zip).
4. Замена: новый файл копируется рядом как `GrazySAI.new`, затем
   - Windows: работающий `GrazySAI.exe` переименовывается в `GrazySAI.exe.old` (Windows это
     разрешает), `GrazySAI.new` → `GrazySAI.exe`; `.old` удаляется при следующем запуске;
   - Linux: `GrazySAI.new` переименовывается поверх `GrazySAI` (работающая программа продолжает
     работать со старым файлом).
   Справочные файлы рядом с программой (README, руководство) тоже заменяются — только те, что
   уже там лежат.
5. «Перезапустить сейчас» запускает новый файл с теми же аргументами и закрывает окно; пока
   холст не сохранён, кнопка неактивна.

Что нужно: Windows 10 1803 и новее (там есть `curl.exe` и `tar.exe`), в Linux — `curl` и `tar`.
Нет прав на запись в папку программы, нет сети, не совпала сумма — окно пишет причину и
предлагает страницу выпуска.

## Ссылки на GitHub

- Справа в строке меню — «GitHub» (страница проекта).
- «Помощь → GrazySAI на GitHub», ссылка в «О программе».
- Браузер открывается через `xdg-open` в Linux и `url.dll,FileProtocolHandler` в Windows.

## Проверка без выпуска

`PAINT_FAKE_VERSION=0.8.4` — программа считает себя этой версией и находит настоящий последний
выпуск; `PAINT_UPDATE_EXE=путь` — ставить новый файл по этому пути, а не поверх себя;
`PAINT_UPDATE_CHECK=off|on` — проверять ли при запуске; `PAINT_SHOW_DIALOG=update` — открыть
окно сразу. Тесты `update::tests` — SHA-256, сравнение версий, разбор ответа GitHub.
Сверено на скрытом экране: 0.8.4 «нашла» 0.8.5, скачала, файл совпал с выпуском байт в байт,
перезапуск поднял новую версию.

## Переход со старого имени (0.8.41)

До 0.8.41 программа звалась SOsai (репозиторий `grazyping/SOsai`). Чтобы старые версии нашли
обновление:

- репозиторий переименован на GitHub — старый адрес API (`repos/grazyping/SOsai/…`) GitHub
  перенаправляет на новый, `curl -L` по перенаправлению проходит;
- к каждому выпуску (на переходное время) приложены ещё архивы со старым именем
  `SOsai-X-…` — в них папка `SOsai-X-…` и файл `SOsai(.exe)`, но внутри уже GrazySAI
  (`tools/release.sh`). Старая версия ставит его поверх себя; файл на диске сохраняет имя
  `SOsai(.exe)`, дальше обновляется уже по архивам `GrazySAI-…`;
- папка настроек `SOsai` (настройки, недавние файлы, копии для восстановления) при первом запуске
  переезжает в `GrazySAI`; переменная `SOSAI_PAPERTEX` по-прежнему понимается.
