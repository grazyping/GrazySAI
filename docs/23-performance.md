# Скорость на больших холстах

15 октября 2026. Замер на рисунке пользователя `YCH JimTheDoggo1.sai2`: 2300×4096, 191 слой,
204 МБ, на рабочей машине (все ядра).

| Что | Было | Стало |
|---|---|---|
| Чтение `.sai2` | 2,4 с | 0,3 с |
| Запись `.sai2` | 3,9 с | 3,1 с |
| Пересохранение целиком (`paint-cli resave`, со сверкой сведения) | 10,5 с | 4,2 с |
| Показ холста целиком после открытия | — | 0,3 с |

Что сделано:
- пиксели слоёв раскодируются параллельно, у каждого потока свой дескриптор файла
  (`sai2_doc::load`);
- сведённая картинка считается полосами по высоте плитки на всех ядрах (`Document::flatten`) —
  быстрее запись `.sai2` (блок `intg`) и экспорт;
- плитки на экране рисуются пачками на всех ядрах (`render_pending`);
- запись пикселей слоёв и раньше шла параллельно.

Память при чтении этого файла — около 1,3 ГБ (пиксели хранятся по 15 бит на канал в плитках
64×64; пустые плитки места не занимают).

Замер в окне: `PAINT_TIMING=1 GrazySAI файл.sai2` печатает, за сколько холст показан целиком.

Что ещё можно ускорить: кодирование сведённой картинки при записи (в один поток), историю отмены
на диске (сейчас каждая запись истории — копии плиток в памяти).

## Кисть большого размера (0.8.1)

Жалоба пользователя: Карандаш размером 350 — линия появлялась через 5–10 с.

Причина. Самая жёсткая ступень от 20 px ставит отпечатки через 0,85 px, как SAI. При размере 350
это ~1200 отпечатков на 1000 px линии, по ~120 тысяч точек каждый. Для каждой точки искалась
плитка в хеш-таблице, считались корень и степень профиля края.

Что сделано (результат тот же бит в бит — проверено отпечатками результата до и после):

- отпечаток обходится по плиткам: плитка ищется один раз, а не для каждой точки;
- строки обходятся только внутри круга отпечатка;
- внутри круга постоянного покрытия не считаются ни корень, ни профиль;
- точки, уже набравшие плотность отпечатка, пропускаются сразу;
- отпечатки одного движения пера раскладываются по плиткам и считаются на всех ядрах. Каждая
  плитка получает свои отпечатки в прежнем порядке.
- Кисть и Акварель: средний цвет под пачкой считается по плоской сетке, а не по хеш-набору
  точек. Краска кладётся по плиткам параллельно. Размытие Акварели идёт по строкам и полосам
  столбцов на всех ядрах, а буфер копии слоя переиспользуется.

| Линия 1000 px | Было | Стало |
|---|---|---|
| Карандаш 350 | 4,5 с | 0,12 с |
| Карандаш 100 | 0,39 с | 0,05 с |
| Кисть 350 | 13,7 с | 1,0 с |
| Акварель 350 | 40 с | 7,4 с |
| Акварель 100 | — | 0,7 с |

Тесты: `big_pencil_speed`, `big_mixing_speed` (замеры, `--ignored`), `mixing_brushes_fingerprint`,
`mixing_brushes_fingerprint_large`, `parallel_blur_is_bit_exact` (неизменность результата).

Акварель крупного размера (0.8.8): размытие, как в SAI, идёт по уменьшенной копии слоя (уровень
`⌊log₂ D⌋ − 4`, до 1/8): точка копии — среднее квадрата 2^уровень, проходы скользящего среднего —
в точках копии, обратно — двулинейно. Копия держится по плиткам и пересчитывается только там, где
слой изменился; вес размытия и наложение считаются полосами и плитками параллельно. Акварель
350 px: 7,4 → 2,0 с на 1000 px линии; сверка с живой SAI не ухудшилась (4,4 / 8,1 / 12,9 / 8,9 / 9,3
против 4,2 / 8,3 / 13,1 / 8,9 / 9,3). Ядро уменьшения у SAI вызывается через таблицу форматов
плиток и не дочитано — у нас простое среднее.

## Кисти до 5000 px и предпросмотр фильтров (0.9.7)

Жалоба пользователя: кисти и фильтры работают рывками и с задержками; нужна плавность для
кистей вплоть до 5000 px (наибольший размер сетки SAI).

Замер: холст 4000×3000, мазок длиной 1500 px, нажим 0,4–1 (тест `huge_brush_speed`, `--ignored`;
он же печатает отпечатки результата — они до и после совпали во всех случаях).

| Мазок | 500 px | 1500 px | 5000 px |
|---|---|---|---|
| Карандаш | 0,57 → 0,22 с | 1,50 → 0,25 с | 5,11 → 0,65 с |
| Кисть | 1,17 → 0,18 с | 3,35 → 0,27 с | 11,68 → 0,82 с |
| Акварель | 1,35 → 0,31 с | 3,79 → 0,53 с | 13,50 → 1,69 с |

Что сделано:
- маска самой жёсткой ступени (`add_to_hard_mask`) — по плиткам, большие отпечатки на всех ядрах
  (раньше — поиск плитки в хеш-таблице на каждую точку);
- строки отпечатка (`for_rows`) — только в нужных строках и столбцах (плитка, полоса потока);
  покрытие строки — одним циклом в буфер, маска строки — отрезками по плиткам; круг постоянного
  покрытия — без корня и при маске жёсткости;
- средний цвет под пачкой — полосами на всех ядрах; сумма целая (точка — доли 2⁻¹⁵), поэтому
  порядок сложения не меняет итога;
- сетки пачки (флажки пробы, веса размытия Акварели) выделяются и заполняются полосами в своих
  потоках — у отпечатков 5000 px это сотни мегабайт;
- выделение — плиткой, а не поиском на каждую точку; копия уровня для размытия — отрезками;
- обычный штрих накладывает изменённые плитки слоя на всех ядрах (`live_paint`);
- в окне: точки пера идут в очередь, за кадр рисуется не дольше ~25 мс — окно не замирает,
  штрих догоняет перо за несколько кадров (как в SAI); перо поднято — остаток дорисовывается;
- точки для текстур экрана переводятся в потоках пересчёта плиток, а не в кадре;
- предпросмотр фильтра считается в фоновом потоке (пока считается — значок в окне фильтра),
  OK берёт готовый предпросмотр, а не считает второй раз.

Кадр в окне при таком мазке (Xvfb, без видеокарты; `PAINT_FRAMES=1` печатает по каждому штриху
кадры, среднее, 95 % и худший, доли счёта, пересчёта плиток и текстур):

| Кадр, среднее / худший | 1500 px | 5000 px |
|---|---|---|
| Карандаш | 98 / 347 → 7 / 19 мс | 605 / 943 → 44 / 86 мс |
| Кисть | 768 / 1950 → 7 / 23 мс | 1531 / 1531 → 65 / 187 мс |
| Акварель | 537 / 1190 → 24 / 50 мс | 1771 / 1771 → 122 / 383 мс |

Для замеров в окне: `PAINT_CANVAS=4000x3000` (новый холст), `PAINT_BRUSH=3` (номер кисти сетки),
`PAINT_BRUSH_SIZE=5000`, `PAINT_VIRTUAL_PEN=штрих.csv` (см. `virtual_pen.rs`).

Что ещё можно: одна пачка Акварели 5000 px всё ещё занимает до ~0,3 с (размытие уровня и
наложение); счёт штриха можно увести из потока окна целиком.

## Число ядер — один раз (0.9.9)

`std::thread::available_parallelism()` в Linux на каждый вызов читает cgroup-файлы — десятки
микросекунд. Его спрашивали в горячих местах: при каждом движении пера (раскладка отпечатков по
плиткам), в каждой пачке смешивающей кисти, при каждой перерисовке слоя контура. Теперь число
ядер считается один раз (`paint_core::threads()`). Перерисовка двух штрихов контура: 297 →
7,9 мс (тест `linework_render_speed`, `--ignored`), то есть «Узлы» и «Нажим» больше не отстают от
пера. В Windows вызов и раньше был дешёвым.

Правка контура перерисовывает слой раз за кадр, а не на каждое движение пера.
