# Формат `.sai2`: что выяснено по образцам

Источники: три файла пользователя в `~/SAI2` (два пробных 100×100 и настоящий рисунок 2300×4096,
204 МБ, 191 слой) и разбор оригинального `sai2.bak` в Ghidra 12.1.4 (13 октября 2026) — по нему
установлено, как сжаты пиксели. Программа-образец не запускалась. Числа — little-endian.
Пометка «?» — предположение, не подтверждённое проверкой.

Проверка: декодер в `crates/paint-formats` читает все 171 растровый слой настоящего рисунка без
ошибок; сведённая картинка (`paint-cli sai2 <файл> <out.png> 5`) выглядит как законченный рисунок
с правильными цветами.

## Заголовок (64 байта)

| Смещение | Размер | Что |
|---|---|---|
| 0x00 | 16 | Подпись `SAI-CANVAS-TYPE0` |
| 0x10 | 4 | Признаки холста, по байтам: 0 — всегда 0; 1 — **фон** (поле холста +0x249 SAI 2017): младшие 4 бита 0 — прозрачный, 1 — непрозрачный; старшие — вид (прозрачный показывается: 0 светлой шашкой, 1 тёмной, 2 белым, 3 чёрным, 4 цветом из 0x38; непрозрачный: 0 белый, 1 чёрный, 2 цвет); 2 — не больше 3; 3 — 0 или 1 (`1` у рисунка с миниатюрой). Проверено по коду чтения SAI. |
| 0x14 | 4 | Ширина, px |
| 0x18 | 4 | Высота, px |
| 0x1C | 4 | Разрешение печати, точек на сантиметр × 65536 (37.795 = 96 dpi, 28.35 = 72 dpi) |
| 0x20 | 4 | Число записей в оглавлении |
| 0x24 | 4 | Номер, связанный со слоями: последний выданный или текущий слой (?) |
| 0x28 | 16 | Нули |
| 0x38 | 4 | Цвет фона холста R, G, B и `ff` («Canvas Background Color», по умолчанию серый 80 80 80) |
| 0x3C | 4 | «Layer Effect Color» — метка `norm`, `vivd`, `deep`, `mult`, `ver1` (байт холста +0x23d = 0…4) |

## Оглавление

Сразу после заголовка, по 16 байт на запись: метка (4 символа), номер (u32), смещение от начала
файла (u64). Длина блока — до следующего по смещению блока.

| Метка | Что | Сколько |
|---|---|---|
| `thum` | Миниатюра; внутри метка `jssf` и таблицы, похожие на JPEG | 0 или 1 |
| `intg` | Сведённое изображение целиком | 1 |
| `layr` | Описание слоя, номер = идентификатор слоя | по одному на слой |
| `lpix` | Пиксели слоя, номер = идентификатор слоя | у растровых слоёв |

Порядок записей `layr` в оглавлении — порядок слоёв в стопке (сверху вниз, ?).

## Блок `layr`

| Смещение | Размер | Что |
|---|---|---|
| 0 | 4 | `layr` |
| 4 | 4 | Идентификатор слоя |
| 8 | 4 | 0 |
| 12 | 4 | Порядковый номер; старший бит встречается у слоёв внутри папок (?) |
| 16 | 4 | Вид: `norm` — растровый, `fold` — папка |
| 20 | 8 | Нули |
| 28 | 16 | Область слоя, четыре i32 в блоках по 32 px: лево, верх, ширина, высота. Отсчёт от левого верхнего угла холста; лево и верх бывают отрицательными, слой может выходить за холст |
| 44 | 4 | Режим наложения: `norm`, `mult`, `scrn`, `add `, `dark`, `litn`, `drkc` (встреченные) |
| 48 | 4 | Непрозрачность, 0–100 |
| 52 | 2 | Флаги (0, 1, 2 — обтравка, защита прозрачности ?) |
| 54 | 1 | Видимость (1 — виден) |
| 55 | 1 | Флаги (0x01, 0x40 — у папки, вероятно «раскрыта») |
| 56 | … | Вложенные блоки: метка, длина u32, данные |

Вложенные блоки: `name` — число символов u16 и имя в UTF-16; `ptex` — бумага слоя (`docs/24-paper.md`).

## Пиксели слоя: блок `lpix`, сжатие `dpcm`

Слой разбит на блоки 32×32 px. Блок `lpix`:

1. метка `dpcm`;
2. по одному u32 на каждую строку блоков (их столько, какова высота области слоя) — длина данных
   строки; по этим числам строки можно читать независимо;
3. данные строк подряд; в конце выравнивание до 4 байт.

Строка блоков — цепочка записей. Каждая начинается маркером из двух байт `FF xy`: `y` — младшие
четыре бита номера блока по горизонтали (контроль разметки), `x` — вид записи.

| `x` | Запись | Данные после маркера |
|---|---|---|
| `0` | Пропуск пустых блоков | u16 `n` — пусто `n + 1` блоков |
| `5` | Блок одного цвета | один пиксель, 8 байт; все нули — пустой блок |
| `A` | Блок с картинкой | u16 длина (до 0x3000), затем битовый поток этой длины |
| `F` | Конец строки | — (номер блока равен правому краю области) |

**Пиксель:** четыре u16 в порядке синий, зелёный, красный, альфа; 0x4000 = 1.0; цвет
предумножен на альфу.

**Блок с картинкой** хранит не значения, а поправки к предсказанию. Поток битов читается от
младшего бита к старшему. Сначала идут 1024 поправки синего канала, затем зелёного, красного,
альфы. Код одной поправки:

1. посчитать нули до первой единицы — `z` (не больше 7), единицу пропустить;
2. прочитать ещё бит `b`; номер кода `k = 2·z + b`;
3. `k = 0` — поправка 0;
4. `k = 1…14` — прочитать `k` бит (число `m`) и бит знака; модуль поправки `2^k + m − 1`;
5. `k = 15` — серия нулей: прочитать 7 бит (число `n`), подряд идут `n + 8` нулевых поправок.

**Восстановление** идёт по строкам блока слева направо, каналы независимо, арифметика
16-битная. Предсказание = «слева + сверху − сверху-слева», обрезанное до 0…0x4000; за границей
блока соседи равны нулю. Значение = предсказание + поправка. В блок пишется значение, обрезанное
до 0…0x4000 и не больше альфы этого же пикселя; а «слева» для следующего пикселя — значение до
этой обрезки.

Сведённое изображение `intg` использует родственную процедуру (ниже). Маски слоя (`lmsk`, `mpix`) —
`docs/26-layer-masks.md`.

## Чего в образцах не было

Слои контура, фигуры, текст, маски, линейки перспективы — их метки неизвестны.

## Описание слоя полностью (по коду записи в оригинале)

Заголовок 56 байт, поля уточнены:

| Смещение | Что |
|---|---|
| 12 | Служебный номер слоя (к вложенности отношения не имеет) |
| 16 | Вид: `norm` растровый, `fold` папка, `liwk` контур, `shap` фигуры, `text` текст, `pers` линейка перспективы, `grid` сетка перспективы |
| 52 | **Глубина вложенности**: 0 — верхний уровень. Слой принадлежит ближайшей папке выше по списку с глубиной на единицу меньше. Предел: 10 |
| 53 | Замки: бит 0 — сохранять непрозрачность, бит 1 — рисование, бит 2 — перемещение, бит 7 — всё |
| 54 | Бит 0 — видимость; бит 7 — отметка (вероятно, «источник выбора») |
| 55 | Бит 0 — обтравка («Прикрепление»); бит 6 — папка раскрыта; бит 7 — ? |

Метки режимов наложения: `pass` (папка «насквозь»), `norm`, `mult`, `scrn`, `over`, `sub ` («Тень»),
`add ` («Сияние»), `sbad` («Тень/Сияние»), `burn`, `ddge`, `bndg`, `dark`, `cbrn`, `lbrn`, `drkc`,
`litn`, `cddg`, `lddg`, `litc`, `slit`, `hlit`, `vlit`, `llit`, `plit`, `hmix`, `diff`, `excl`, `fsub`,
`fdiv`, `hue `, `sat `, `col `, `lum `.

Вложенные блоки после заголовка (метка, длина u32, данные; в конце нулевая метка):

| Метка | Что |
|---|---|
| `name` | Имя: u16 число символов, UTF-16 |
| `ptex` | Бумага слоя: u16 сила 0–100, u16 масштаб 10–500, u16 флаг, u16 длина имени, имя текстуры из папки `papertex` (`docs/24-paper.md`) |
| `frng` | Кайма: метка `watr`, u16 ширина 1–15, u16 сила 0–100 (`docs/25-layer-effects.md`) |
| `ceff` | Двухцветный: метка `cbin`, u32 порог 0–100, u32 (`docs/25-layer-effects.md`) |
| `lmsk` | Маска слоя: номер, лево, верх, ширина, высота, три флага |
| `lflo`, `mflo` | Служебные области папки и маски |

Другие блоки оглавления: `mask` и `mpix` (маска и её пиксели, один канал), `fpix`, `liwk`, `shap`,
`text`, `pers`, `grid`.

Слои контура (`liwk`) и фигур (`shap`) хранят только кривые — блок оглавления с той же меткой и
номером слоя; блока `lpix` у них нет. Устройство кривых — `11-linework-shapes.md`, раздел 3;
чтение — `paint-formats/src/sai2_vector.rs`.

## Сведённое изображение: блок `intg`

Картинка, которую сохранил сам образец; читается и служит эталоном для проверки. Блоки 256×256,
после метки `dpcm` — по одному u32 на блок, затем блоки по строкам: маркер `FF` и номер блока в
строке; каждая строка пикселей — отдельный битовый поток с теми же кодами, выровненный по байту;
в конце строки блоков — маркер с числом блоков. Пиксель — синий, зелёный, красный, альфа по
8 бит; предсказание то же, в пределах блока.

**Число каналов** в файле не записано: SAI выводит его из байта фона в заголовке (0x11): младшие 4
бита 0 (прозрачный фон) — 4 канала с альфой, иначе 3 (только цвет, сведение на фоне). Читает
строго так, и обозреватель файлов SAI при расхождении пишет «The contents of this file is broken»
(ошибка 0x20016; так же — любое чтение за концом файла). У файлов SOsai до 0.9.3 при прозрачном
фоне в заголовке `intg` писался с 3 каналами — SAI показывал вместо миниатюры «ERROR». С 0.9.3
число каналов и сведение (без подложки при прозрачном фоне) берутся из байта фона; тест
`intg_planes_follow_the_header_background`, проверка чужих файлов — `GRAZYSAI_INTG_CHECK`.

## Сверка сведения с эталоном (13 октября 2026)

| Файл | Точно совпало | Средняя разница на канал |
|---|---|---|
| `пинг.sai2`, `пинг1.sai2` | 100% | 0 |
| `YCH JimTheDoggo1.sai2` | 56% (83% в пределах 2 единиц из 255) | 1,41, наибольшая 30 |

Что даёт остаток расхождений на настоящем рисунке:

- бумага слоёв (`ptex`, 13 слоёв) накладывается (`docs/24-paper.md`): совпадение 92 % точно, остаток — округление;
- округление: образец считает в целых числах, ядро — в дробных;
- режимы «Сияние» и «Темнее цвет» сделаны по догадке, подтверждённой сверкой (с ними совпадение
  выросло с 42% до 56%), точные формулы из кода не взяты.

Текстовые слои — `docs/30-text-layers.md`; линейки перспективы (`pers`, `grid`) сохраняются как были.

## Запись (paint-rs, 14.10.2026)

`crates/paint-formats/src/sai2_write.rs` пишет файл в той же раскладке, что образец (по
`пинг1.sai2` и коду записи `sai2_save_file`): заголовок (в 0x24 — номер верхнего слоя, в 0x38 —
`80 80 80 ff` и `norm`), оглавление `intg` → `layr` сверху вниз → `lpix`; область каждого слоя —
весь холст в блоках 32 px (слой за пределами холста образец отвергает, ошибка `0x20025`);
служебный номер в `layr` — снизу вверх с 1; имя дополнено до 4 байт.

- `lpix`: пустые блоки — пропуском, одноцветные — записью `5`, остальные — `A` с поправками.
- `intg`: таблица u32 на блок 256×256 — длина его данных вместе с маркером (так её заполняет
  образец); три канала при непрозрачном фоне холста, четыре — при прозрачном.
- Слои контура и фигур пока пишутся растром (кривые теряются).

Проверка: все семь файлов пользователя (`paint-cli resave`) читаются обратно с тем же сведением
(разница 0–1), 191 слой большого рисунка — 200,5 МБ против 204,3 у образца, запись 3,9 с
(слои кодируются параллельно). Тест `written_sai2_reads_back_the_same`. Открывает ли образец
наши файлы — проверить в лицензированной SAI пользователя (наша ограниченная не открывает).

## Миниатюра `thum` (пишется с 0.8.39)

Блок: u32 ширина, u32 высота, метка `jssf`, затем u16 ширина, u16 высота, u16 число каналов (3),
две таблицы квантования по 64 байта (в порядке зигзага; яркость 2, 2, 2 … 16 и цвет 6 … 37 —
качество 80), затем по каждой строке блоков 8 px: длина (u16; если больше 0x7FFF — сначала
старшая половина с битом 0x8000) и данные строки.

Данные — обычный JPEG без прореживания цвета: 4:4:4, по блоку 8×8 на Y, Cb, Cr подряд,
стандартные таблицы Хаффмана (приложение K; у цвета — таблицы цвета), после байта `FF` вставлен
`00`, строка добивается единицами, предсказание DC сбрасывается в начале строки. (Прежний сбой
разбора на 10-й строке был опечаткой в нашей таблице AC цвета.)

Размер — как у SAI 2017: холст уменьшается вдвое, пока большая сторона не меньше 512 (не больше 8
раз), размеры округляются вверх; холст меньше 512 px миниатюры не получает (2300×4096 → 144×256,
1000×1000 → 500×500). Блок идёт в оглавлении первым, перед `intg`.

GrazySAI (`jssf.rs`): уменьшение средним по квадрату, прозрачное — на белом; разбор и запись
сверены: наш разбор миниатюр SAI совпадает с независимым (разница ≤ 1), наша миниатюра того же
рисунка отличается от миниатюры SAI в среднем на 2,6 из 255. Проверка глазами —
`tests/jssf_look.rs` (`GRAZYSAI_JSSF_IN`, `GRAZYSAI_JSSF_OUT`).

## Пересохранение без потерь (0.8.23)

Файлы пользователя после `paint-cli resave`: сведение совпадает (разница 0), блоки `text`, `liwk`
— байт в байт. Отличаются номера слоёв (GrazySAI нумерует по порядку), область пустых слоёв (SAI
пишет 0, GrazySAI — весь холст), сжатие `lpix`/`intg` (то же содержимое). Разрешение печати (0x1C)
теперь хранится в документе и пишется обратно.
