# Свои кисти и плагины: как это можно сделать

Сбор сведений 21.10.2026 перед разработкой. Совместимость с другими программами — не цель:
форматы и API свои. Замеры сделаны на рабочей машине (16 потоков), пробные проекты — во временной
папке, в репозиторий не входят.

## 1. Что уже есть

- Движок кисти (`paint-core/src/stroke.rs`): круглый отпечаток SAI, отпечаток-картинка (`Tip`:
  поворот, толщина, по мазку, набор картинок по порядку или вразнобой), форма-«пятно», щетина,
  текстура, смешивание с холстом (`MixParams`), нажим на размер и плотность.
- Инструменты сетки хранятся в `settings.txt` (`tool.N.*`, `brush.N.*`); отпечатки — в папке
  настроек `tips/`, текстуры — `brushtex/`.
- Импорт чужих кистей (CSP, Krita, GIMP, Photoshop) в эти же величины.
- Фильтры (`FilterKind`) — окно с предпросмотром, работа над пикселями слоя.

Чего нет: своего файла кисти (кисть нельзя передать другому человеку), окна-редактора кисти,
общей «динамики» (сейчас только нажим → размер и плотность), любого способа добавить код.

## 2. Как устроено у других (для идей, не для совместимости)

| Программа | Кисти | Плагины |
|---|---|---|
| MyPaint | `.myb` (JSON): ~45 параметров, у каждого — базовое значение и кривые от 9 входов (нажим, скорость ×2, случайность, ход мазка, направление, наклон ×2, свой вход) | — |
| Krita | `.kpp` (PNG + XML), наборы `.bundle` (zip); у каждого параметра — датчики с кривыми | Python (меню, окна, доступ к документу); движки кистей — C++ внутри программы |
| GIMP 3 | `.gbr`, `.gih`, `.vbr`; динамика отдельно | отдельные процессы (C, Python, Lua, JS) по своему протоколу |
| Aseprite | — | Lua: zip-архив `.aseprite-extension` с `package.json`, команды меню, окна-диалоги |
| CSP, Photoshop | свои форматы | C++-библиотеки по SDK производителя |

Вывод: удачная модель кисти — MyPaint/Krita («вход → кривая → параметр»), удачная упаковка
плагинов — Aseprite (zip + описание + код, установка из меню).

## 3. Кисти: свой формат и редактор

### Файл кисти `.gsbrush` (и набор `.gsbrushes`)

Zip-архив:

```
brush.toml      — имя, автор, версия формата, вид (карандаш, кисть, акварель…), все параметры
tip.png         — отпечаток (и tip.2.png… — набор), если не круг
texture.png     — текстура, если есть
preview.png     — образец мазка для списка
```

`brush.toml` — читаемый текст: его можно править руками и хранить в git. Набор кистей —
тот же zip с папками на каждую кисть. Чтение и запись — `paint-formats` (zip уже есть в ORA).

### Динамика вместо одного нажима

Обобщить «нажим → размер/плотность» до таблицы, как у MyPaint:

- **входы:** нажим, скорость, наклон, поворот пера, направление мазка, ход мазка (от начала),
  случайность, время;
- **выходы:** размер, плотность, поток, жёсткость, угол и толщина отпечатка, разброс
  (смещение отпечатка), число отпечатков, оттенок/насыщенность/яркость цвета, смешивание;
- **связь:** у каждой пары — кривая (у нас уже есть `curve::PressureCurve`, монотонная
  Фрича — Карлсона; для «случайности» и «направления» нужна и немонотонная).

Считается один раз на отпечаток — тысячи раз за мазок, это дёшево (см. замер вызова ниже).

### Окно «Редактор кисти»

- слева — разделы как сейчас (Форма, Текстура, Смешивание), плюс «Динамика»: список связей
  «вход → выход» с редактором кривой (`sai_ui::curve_editor` уже есть);
- справа — полоса пробы: мазок рисуется сразу при каждой правке (виртуальное перо из
  `virtual_pen.rs` даёт одинаковый мазок с нажимом от слабого к сильному);
- «Отпечаток»: импорт картинки, простой генератор (круг, квадрат, брызги из N точек, шум,
  «уголь» — круг с шумом по краю), рисование отпечатка мышью на маленьком холсте 128×128;
- кнопки «Сохранить кисть…», «Сохранить набор…», открытие `.gsbrush` перетаскиванием.

## 4. Плагины: варианты движка

Пробы собраны под Linux и под нашу сборку для Windows (`x86_64-pc-windows-gnullvm`, llvm-mingw):
собираются все варианты; пробный wasmtime для Windows запускается под Wine.

| Движок | Язык плагина | +к размеру программы¹ | Фильтр 4 Мп² | Вызов функции³ | Сборка |
|---|---|---|---|---|---|
| свой код (для сравнения) | Rust | — | **6 мс** | — | — |
| wasmtime 50 (Cranelift, JIT) | Rust, C, Zig, AssemblyScript… → WebAssembly | +15 МБ | **15 мс** (+21 мс на компиляцию модуля) | 0,02 мкс | +70 с |
| wasmi 2.0 (интерпретатор) | то же WebAssembly | +3,4 МБ | 172 мс | 0,06 мкс | +15 с |
| Lua 5.4 (mlua, исходники Lua в комплекте) | Lua | +0,6 МБ | 1045 мс | 0,06 мкс | +10 с |
| Rhai 1.26 | Rhai (похож на Rust/JS) | +3,7 МБ | ~12 600 мс | — | +18 с |

¹ к пустой программе; GrazySAI сейчас 21 МБ. ² «яркость/контраст» над 2048×2048 RGBA.
³ вызов «динамики» на один отпечаток.

Что из этого следует:

- **На каждый отпечаток** (динамика, выбор отпечатка, разброс) годится любой движок: вызов
  стоит доли микросекунды.
- **На каждую точку** (фильтры, свой отпечаток-формула, свой режим смешивания) годится только
  WebAssembly; wasmtime почти как свой код (×2,5), wasmi — ×28 (фильтр на большом холсте —
  секунды), Lua — ×170, Rhai — неприемлемо.
- **Безопасность.** Плагин — чужой код. WebAssembly изолирован по устройству: нет доступа к
  файлам и сети, пока программа сама не даст функцию; есть ограничение памяти
  (`ResourceLimiter`) и прерывание зависшего кода (fuel / epoch у wasmtime, fuel у wasmi).
  У Lua изоляцию надо собирать самим: убрать `io`, `os`, `require`, `load` с байткодом, ставить
  счётчик инструкций и предел памяти — сделать можно, но проще ошибиться.
- **Простота для автора.** Lua пишется в любом редакторе и сразу работает; WebAssembly
  требует компилятора (для Rust — `cargo build --target wasm32-unknown-unknown`), зато
  плагин — один файл `.wasm`, одинаковый для Windows и Linux.

Отвергнуто:

- **родные библиотеки** (`.dll`, `.so`) — нет устойчивого ABI у Rust, отдельная сборка под
  каждую систему, сбой плагина роняет программу, никакой изоляции;
- **отдельный процесс** (как в GIMP) — надёжно, но нужен свой протокол обмена и
  копирование пикселей между процессами; оставить на потом, если понадобятся плагины на
  Python.

### Предложение: два уровня

1. **Lua — для действий и простых вещей**: команды меню, макросы («создать 3 слоя и залить»),
   своя динамика кисти, генератор отпечатка, импорт палитр. Окна плагина описываются
   данными (`{ slider "Радиус" 1..100, checkbox "Края" }`), программа рисует их сама в egui —
   плагин не трогает интерфейс напрямую.
2. **WebAssembly (wasmtime) — для работы с пикселями**: фильтры, свой отпечаток-формула, свои
   режимы наложения, чтение форматов файлов. Программа передаёт плитку 256×256 и параметры,
   получает плитку обратно; плитки обрабатываются в нескольких потоках (у каждого потока свой
   экземпляр модуля), как сейчас встроенные фильтры.

Если +15 МБ и +70 с сборки — слишком дорого, второй уровень можно начать на wasmi (тот же
формат плагинов) и перейти на wasmtime позже без изменений у авторов плагинов.

## 5. Пакет плагина

`.gsplugin` — zip:

```
plugin.toml   — id, имя, версия, автор, версия API, разрешения, что добавляет
main.lua      — и/или filter.wasm
icon.png, README.md, lang/*.txt — переводы строк плагина (как lang/ программы)
```

```toml
id = "example.soft-glow"
name = "Мягкое свечение"
version = "1.0.0"
api = 1
permissions = []            # "read-file", "write-file", "network" — по запросу, с вопросом
[[filter]]
menu = "Фильтр/Свет/Мягкое свечение"
wasm = "filter.wasm"
params = [ { id = "radius", kind = "slider", min = 1, max = 100, default = 20 } ]
[[command]]
menu = "Слой/Три слоя для покраски"
lua = "main.lua"
function = "three_layers"
```

Установка — «Помощь → Плагины…» (список, включить/выключить, удалить) или перетаскиванием
файла в окно. При установке — окно с разрешениями. Плагины лежат в папке настроек
`plugins/`.

## 6. API (первая версия)

Для Lua и WebAssembly один набор понятий:

- документ: размер, слои (имя, видимость, режим, непрозрачность, пиксели плитками), выделение,
  текущий цвет, текущий инструмент;
- изменения — только через историю (одна запись на действие плагина: «Отменить» откатывает
  всё, что сделал плагин);
- фильтр: `process(tile_in, tile_out, params, x, y)`; предпросмотр — тот же вызов на видимых
  плитках;
- кисть: `dynamics(input) -> outputs` на отпечаток, `tip(size, angle) -> картинка` с кешем;
- окно параметров — описание полей, значения приходят в плагин.

## 7. Инструменты и инструкции для авторов

- `paint-cli plugin new <имя> --lua|--rust` — заготовка с примером и сборкой;
  `paint-cli plugin check` — проверить `plugin.toml`, загрузить модуль, прогнать на тестовой
  картинке; `paint-cli plugin pack` — собрать `.gsplugin`;
- `docs/plugins.md` (ru и en): «первый плагин за 10 минут», справочник API, примеры: инверсия,
  размытие, свой отпечаток, динамика «перо-кисть», команда меню;
- `docs/brushes.md`: как сделать кисть в редакторе, формат `brush.toml`, передача набора;
- примеры плагинов — в репозитории (`plugins/examples/`), каждый с тестом.

## 8. Порядок работ (предложение)

1. Свой файл кисти `.gsbrush`: сохранить / открыть инструмент сетки и набор (небольшая работа).
2. Динамика «вход → кривая → выход» в движке и в настройках.
3. Окно «Редактор кисти» с полосой пробы и генератором отпечатка.
4. Плагины Lua: пакет, установка, команды меню, окно параметров, своя динамика кисти.
5. Плагины WebAssembly: фильтры по плиткам в потоках, затем свой отпечаток и режимы.
6. `paint-cli plugin …`, инструкции, примеры.

Пункты 1–3 не зависят от выбора движка плагинов и полезны сами по себе.

## 9. Решения (21.10.2026) и итоговое устройство

Ответы пользователя:

1. Плагины и кисти пишет **кто угодно** — значит, код плагина чужой и должен работать в
   песочнице, без доступа к файлам, сети и системе.
2. Основную программу не раздувать: **отдельная программа-мастерская** со своим
   инструментарием; обе открыты одновременно, «Экспорт в GrazySAI» — и плагин или кисть сразу
   появляются в рисовалке для проверки.
3. Общего магазина пока нет — **только файлы**.

### Две программы

| | GrazySAI (рисовалка) | GrazySAI Studio (мастерская) |
|---|---|---|
| Кисти | открыть `.gsbrush`, рисовать | редактор кисти с полосой пробы, генератор отпечатка, наборы |
| Плагины | только **исполнение**: Luau + wasmi | заготовки, редактор кода, проверка на образцах, сборка `.gsplugin` |
| Размер | +≈4,6 МБ (Luau 2,2 + wasmi 2,4) | сколько нужно |

Общий код — отдельная библиотека `paint-plugin` (описание пакета, песочница, API), её используют
обе программы: плагин ведёт себя в мастерской так же, как в рисовалке.

### Исполнение плагинов

Дополнительные замеры:

| | Размер (без символов) | Фильтр 4 Мп | Вызов |
|---|---|---|---|
| Luau (mlua, песочница) | +2,2 МБ | ~1000 мс | 0,3 мкс |
| wasmi, 1 поток | +2,4 МБ | 172 мс | 0,06 мкс |
| wasmi, 16 потоков (свой экземпляр на поток) | — | **69 мс** | — |
| wasmtime / wasmtime + Winch | +11,3 / +10,5 МБ | 15 / 32 мс | 0,02 / 0,04 мкс |

- **Luau** (Lua от Roblox, сделана для чужих скриптов): плагин — просто текст, компилятор автору
  не нужен. В режиме песочницы (`Lua::sandbox`) проверено: нет `io`, `dofile`, `load`, у `os` нет
  `execute`/`remove`, общую таблицу `_G` менять нельзя. Плюс счётчик времени и предел памяти.
  Под Windows Luau (C++) собирается с llvm-mingw, если вкомпоновать libc++ статически
  (`-L native=…/x86_64-w64-mingw32/lib`, `CXXSTDLIB_…=static=c++`) — проверено под Wine.
- **wasmi** для работы с пикселями: песочница по устройству WebAssembly, плагин — один `.wasm`
  для всех систем. Медленнее wasmtime, но по плиткам в потоках — 69 мс на 4 Мп, этого хватает;
  wasmtime (+11 МБ) не нужен. Загрузка заранее скомпилированного кода wasmtime для чужих
  плагинов не годится: такой файл — уже машинный код без проверки.
- Авторам плагинов на WebAssembly нужен свой компилятор (Rust, C, Zig…); мастерская находит его и
  собирает, а без него предлагает Luau.

### Связь мастерской с рисовалкой

Через папку, без сети и без открытых портов:

1. «Экспорт в GrazySAI» кладёт пакет в папку настроек рисовалки, `plugins/dev/` (кисть —
   `brushes/dev/`), и обновляет файл-отметку.
2. Рисовалка раз в секунду смотрит время изменения отметки (дешёвый `stat`), подгружает новое
   и пишет в строке состояния «Плагин … обновлён» — закрывать программы не нужно.
3. Плагины из `dev/` помечены как проверяемые; ошибки плагина (с номером строки Luau) видны в
   окне «Плагины» рисовалки и в мастерской.

### Позже: бесплатный общий каталог

Без своего сервера: отдельный открытый репозиторий на GitHub с файлом-списком (`index.json`:
имя, автор, версия, ссылка на файл в Releases, SHA-256). Автор добавляет свою кисть или плагин
запросом на слияние, файлы хранит GitHub Releases. Программа читает список по HTTPS так же, как
сейчас проверяет обновления, и проверяет SHA-256 скачанного.

## 10. Порядок работ

1. `.gsbrush`: сохранить / открыть инструмент и набор — в рисовалке.
2. Динамика «вход → кривая → выход» в движке.
3. Библиотека `paint-plugin` и мастерская: редактор кисти с полосой пробы, экспорт в
   рисовалку и подхват на лету.
4. Плагины Luau: пакет, песочница, команды меню, окно параметров, своя динамика кисти;
   заготовки и проверка в мастерской.
5. Плагины WebAssembly (wasmi): фильтры по плиткам, свой отпечаток.
6. Инструкции (ru, en) и примеры; затем каталог.
