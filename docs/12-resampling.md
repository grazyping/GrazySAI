# Пересэмплирование в образце

14 октября 2026. Участок по карте программы выглядел как «попиксельные операции и наложение»;
разбор показал другое: это **геометрия слоя** — отражение, поворот на 90°, свободная
трансформация, изменение размера и разрешения — и **пересэмплирование** пикселей при ней.
Наложение слоёв (режимы смешивания) здесь не лежит; оно уже проверено на живом образце: все 28
режимов совпадают с нашими формулами в пределах 2 уровней (`08-brush-verification.md`).
Имена — `sai2-analysis/rea/names-resample.txt`. Своими словами, листинги вне проекта.

## 1. Режимы

Выбор режима — `resample_select_mode`. Номер режима совпадает с порядком надписей
`SmplMode_*` в таблице интерфейса; они же — пункты «Resample Settings: Dragging / Preview»
панели перемещения и «Resampling Method» диалога разрешения холста.

| № | Режим | Ядро k(x) | Опора, px |
|---|---|---|---|
| 0 | Nearest Neighbor | ближайший пиксель | — |
| 1 | Bilinear | при увеличении треугольник `1 − |x|`; **при уменьшении — усреднение по площади** | 1 |
| 2 | Bicubic | кубика Кейса с **a = −0,8**: `1,2|x|³ − 2,2|x|² + 1` при `|x| < 1`; `−0,8|x|³ + 4|x|² − 6,4|x| + 3,2` при `1 ≤ |x| < 2` | 2 |
| 3 | Lanczos 2 | `sinc(x)·sinc(x/2)` | 2 |
| 4 | Lanczos 3 | `sinc(x)·sinc(x/3)` | 3 |

Коэффициент бикубики −0,8 — не обычные −0,5 или −0,75: картинка резче, с заметнее
ореолом на контрастных краях. Это надо повторить в точности, если хотим тот же вид.

Ядро не считается для каждого пикселя: режим один раз заполняет таблицу из 512 значений с шагом
1/64 px (от −4 до +4), а при пересчёте значение берётся линейной интерполяцией между соседними
элементами таблицы.

## 2. Как применяется

Функции-ядра (по шесть на режим; Bicubic и Lanczos 2 пользуются одними функциями, отличается
только таблица) раскладываются по слоям: у растрового слоя три указателя (`0x520`–`0x530` в
слое), у маски слоя — свои три. Так один и тот же код трансформации работает и с цветом
(4 канала по 16 бит), и с маской (1 канал).

Из прочитанного ядра масштабирования (`resample_cubic2_color_a`):
- координаты — в фиксированной точке, 1 px = 4096;
- при **уменьшении** ядро растягивается во столько раз, во сколько уменьшается картинка
  (как в обычном фильтре сглаживания при уменьшении), при увеличении — нет;
- веса нормируются на сумму — края слоя не темнеют;
- проход по строкам плиток 32×32.

Отражение и поворот на 90° (`cmd_layer_flip_rotate90_task`) пересэмплирования не
требуют и выполняются отдельно, фоновой задачей.

Ядро масштабирования работает в два прохода: первый (`_a`) по вертикали копит для каждого
столбца две суммы — по всем отсчётам и только по «близким» (ближе единицы ядра); второй (`_b`)
по горизонтали берёт для «близких» по горизонтали отсчётов полную сумму, для дальних — только
«близкую». Так и получается окно без углов. Затем деление на сумму взятых весов и ограничение:
альфа не больше `0x4000`, цвет от 0 до альфы. Имена `_k1`/`_k2` — гипотеза (варианты для
трансформации).

## 3. Для нашего редактора

1. Пять режимов с теми же ядрами, бикубика с a = −0,8; таблица на 1/64 px с линейной
   интерполяцией — дёшево и совпадает с образцом.
2. При уменьшении — растягивать ядро на коэффициент уменьшения, веса нормировать.
3. Одна реализация на цвет и маску.

## 4. Проверка на живом образце

14 октября 2026, сборка 2017-01-19 на скрытом экране. Холст 100×100, залитый чёрным (чтобы он был
непрозрачным и не мешало предумножение), на нём белые линии разной толщины и точки. Снят при
100% (`before.png`), затем Canvas → Change Canvas Resolution на 300%, 150% и 37% в каждом из
пяти режимов, каждый раз снимок и отмена. Снимки — `paint-core/tests/data/resample/`, холст
вырезается из снимка по прямоугольнику, отличному от серого фона (`live/grab-canvas.py`).

Наш код (`paint-core/src/resample.rs`) после двух поправок совпал во **всех 15 случаях с
точностью до 1/255** (98–100% пикселей точно, остальное — округление). Поправки, найденные
сравнением, а не в коде:
- **Bilinear при уменьшении — усреднение по площади**, а не растянутый треугольник (было до 27/255);
- **у Lanczos 3 окно полное**, «углы» отбрасываются только у Bicubic и Lanczos 2 (было до 6/255;
  в коде это, видимо, поле `0x684` режима: 2 — без углов, 1 — полное).

Подтверждено: таблица ядра на 1/64 px, бикубика с a = −0,8, растяжение ядра при уменьшении для
Bicubic и Lanczos, нормировка весов, центр пикселя (i + 0,5)·масштаб. Закреплено тестом
`resampling_matches_the_reference_program`.

Урок съёмки: курсор мыши попадает в снимок — перед снимком уводить его за пределы холста
(первый снимок «до» был испорчен курсором над точкой).
