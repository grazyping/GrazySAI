# Холст, плитки и история в образце

14 октября 2026, разбор участка кода файла `sai2.bak`. Своими словами, с
адресами функций (имена записаны в проект Ghidra, `sai2-analysis/rea/names-canvas.txt`).
Листинги — вне проекта.

## 1. Две сетки плиток

В программе две независимые сетки, и их нельзя путать.

| Сетка | Размер плитки | Для чего |
|---|---|---|
| **Данные слоя** | 32×32 px | Пиксели слоя в памяти, в файле `.sai2` и в истории |
| **Вид** (окно холста) | 16×16 px | Что устарело на экране и что пересчитать при выводе |

### Данные слоя: плитки 32×32

У слоя есть «плоскость» (указатель по смещению `0xe0` в слое). В ней:

- прямоугольник занятых плиток (в единицах плиток);
- для каждой строки плиток — массив ячеек по 8 байт и массив байтов состояния;
- ссылка на **описатель формата**: цвет или маска.

Ячейка плитки бывает трёх видов — те же, что в файле `.sai2`:

| Вид | Что в ячейке | Память |
|---|---|---|
| Пустая | ничего (состояние «нет») | 0 |
| Сплошная | сам цвет, 8 байт, прямо в ячейке вместо указателя | 0 |
| Полная | указатель на буфер 32×32 пикселей | 8 КБ цвета или 2 КБ маски |

Буферы берутся из пулов памяти, отдельных для потоков (`tile_alloc`, `tile_pool_enter` и
`tile_pool_leave`). Пиксель цвета — 4 канала по 16 бит, предумноженный, единица = `0x4000`
(как в файле). Пиксель маски — 16 бит.

Загрузка `.sai2` (`sai2_decode_layer_rows`) раскладывает файл прямо в эту структуру: пропуск
— пустая плитка, «сплошная» — 8 байт в ячейку, сжатая — новый буфер, распаковка и обратное
предсказание методом формата.

### Описатель формата

Две таблицы в данных программы: цвет и маска. В начале — числа, потом
около 34 указателей на функции.

| Поле | Цвет | Маска |
|---|---|---|
| Размер сплошного значения | 8 | 2 |
| Каналов | 4 | 1 |
| Байт в полной плитке | 8192 | 2048 |
| Сплошное значение по умолчанию | — | `0x2000` |

Методы (у цвета; у маски свои с тем же назначением): выделить плитку, войти и выйти из пула,
прочитать пиксель, залить плитку целиком и прямоугольник в ней, скопировать прямоугольник между
плитками, прямое и обратное предсказание (для сжатия), проверить строку и столбец на пустоту,
проверить «все пиксели одинаковые» (так плитка снова становится сплошной), три функции разности
двух плиток (для истории), около 12 ядер закраски (цвет по покрытию, цвет по маске покрытия с
таблицей перевода покрытия в непрозрачность — сюда приходит результат движка кисти).

**Для нашего ядра.** У нас плитки 64×64 и только «пусто/полная». Стоит перейти на 32×32 и
добавить «сплошную» плитку: заливка, очистка, большие однотонные области и чтение `.sai2`
становятся бесплатными по памяти, а формат в памяти совпадает с файлом. Методы формата — готовый
список операций, который нужен нашему слою.

### Вид: плитки 16×16 и флаги

У объекта вида — массив строк, по 16 бит флагов на плитку 16×16 (`view_tileflags_set`,
`view_tileflags_clear`). Каждый бит — «устарел такой-то этап»: при изменении ставятся флаги в
прямоугольнике (выровненном до 16 px, `rect_align16`), потом этапы пересчитываются только для
помеченных плиток.

Пересчёт идёт параллельно: `parallel_run` будит рабочие потоки (их столько, сколько ядер) и
раздаёт им функцию и диапазон строк плиток, `parallel_wait` ждёт конца. Рабочая функция вывода
(`view_render_rows_worker`) для каждой строки плиток вызывает функцию пересэмплирования, выбранную
по масштабу, с аффинным преобразованием вида (сдвиг, масштаб, поворот, зеркало — шесть чисел
двойной точности) и пишет в 32-битный буфер экрана и вспомогательный 16-битный буфер. Сами функции
пересэмплирования — большие ядра на SSE в начале участка.

**Для нашего редактора.** Именно так стоит устроить вывод: свои флаги «устарело» по плиткам
экрана и пересчёт только их, параллельно. Сейчас у нас перерисовка по бюджету на кадр без флагов.

## 2. История (отмена и повтор)

### Устройство

| Уровень | Что это | Функции |
|---|---|---|
| Менеджер | у холста по смещению `0x158`: номер последнего сеанса, текущий открытый сеанс, отменённые | — |
| Сеанс | одна операция пользователя: 64-битный номер, вид операции, флаги, копии маски выделения (если есть выделение), список записей слоёв | `history_begin` (вызывают 53 места) |
| Запись слоя | одна на каждый затронутый слой: номер слоя, вид изменения, данные «до» | `history_add_layer_entry` (62 места) |
| Данные плиток | для плиток слоя — копии «до» и «после» | пишутся в файл в фоне |

Вид изменения в записи слоя — число: 1 и 3 — свойства слоя (сохраняется поле, похожее на
непрозрачность), 4 — что-то размером `0x200`, 5–14 — изменения пикселей и прочего; точный смысл
каждого кода ещё не разобран. Вид операции в сеансе тоже число (2, 6, 0x10, 0x11, 0x33, 0x3a,
0x40…); для части видов отключается проверка «перемещение слоя завершилось».

### Вытеснение на диск

Данные истории не держатся в памяти: фоновая задача (`history_flush_session`) пишет их в файлы
`<папка истории>\<номер>.dat` (`history_open_data_file`; номер файла — 64-битный счётчик, файл
открывается с буфером 64 КБ, у файла счётчик ссылок). Папка истории — внутри папки данных
пользователя (`hisdata`), у каждого холста своя подпапка с шестнадцатеричным номером холста; при
закрытии холста она удаляется.

Запись (`history_write_tile_rows`) идёт по строкам плиток 32×32 слоя. Для каждой пары плиток «до» и
«после» берутся их виды (пустая, сплошная, полная — по 2 бита). В файл пишется заголовок 4 байта:
вид записи, виды обеих плиток, номер плитки. Затем данные, которые готовит один из трёх методов
разности формата:
- обе полные — поканальная разность;
- одна из них сплошная — разность с этим цветом.

После записи копии плиток в памяти освобождаются. Когда файл перерастает примерно 32 МБ, он
закрывается и начинается новый.

Ошибка записи даёт сообщение «Discharging of history data into file was failed».

### Отмена

`cmd_Edit_Undo` ставит в фоновую очередь `undo_task`, та вызывает `history_undo`:
1. Берёт предыдущий сеанс (`history_prev_session`).
2. Если его данные на диске — читает (`history_read_data`).
3. Для каждой записи слоя находит слой по номеру (`canvas_find_layer`) и восстанавливает его
   (`history_restore_layer`).
4. Обновляет вид и панели (`canvas_notify_changed`).

Повтор (`history_redo`) — зеркально. На время работы показывается окно прогресса
(`progress_begin` / `progress_end`).

**Для нашего ядра.** Сейчас у нас отмена по копиям плиток в памяти без ограничения. У образца
три решения, которые стоит взять:
1. Сеанс на операцию с записями по слоям — у нас уже близко.
2. Хранить разность «до/после» по плиткам, а не полные копии; сплошные плитки почти ничего не
   стоят.
3. Вытеснять старые сеансы на диск в фоне.

Число отмен в образце — 100 (по журналу изменений, позже 100–200 при включённом восстановлении
работы).

## 3. Что осталось неясным

- Точный смысл кодов вида операции и вида изменения слоя.
- Формат записей `.dat` целиком (заголовок файла, записи свойств и маски выделения).
- Какой этап отвечает за какой бит флагов вида (`0x800`, `0x1000`, `0x4000`, `0x8000`, `0x1c00`…).
- Функции пересэмплирования вида: какие режимы при каком масштабе (в настройках есть «Bilinear»,
  «Bicubic» и др.).

## 4. Поправки к автоматическим именам

При разборе нашлись ошибки автоматического именования (`09-program-map.md`):
- функции, которые вызывает не только обработчик команд, получили имя команды по ошибке
  (`cmd_Canvas_ChangeSize_1/2` — это окно прогресса; «Redo» и «Cut» — это «Undo» и «Redo»);
- имена по одному коду ошибки ненадёжны: малые константы встречаются и в другом смысле.

Исправлено: 18 имён команд проверены по вызывающим, 73 слабых имени по ошибкам возвращены
к безымянным. Сейчас с именами 685 функций.
